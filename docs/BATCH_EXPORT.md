# 2.2 精选小库导出与 MulimgViewer 排版

## 1. 两个工具怎样分工

先在本工具中按需浏览大库、同步检查细节并邀请同学独立标记。确定典型样本后，按推荐人数等条件筛选，只复制选中的少量原始结果，形成每方法一个文件夹的小库，再用 MulimgViewer 做进一步排版。

**筛选大库 → 推荐人数 N → 确认样本与方法 → 复制小库／下载 ZIP → 使用本机路径 → MulimgViewer。**

小库导出与“论文 PNG 拼图”不同：前者保留一张张原始文件，后者生成组合画布。小库不会缩放、裁剪、增强或重新编码图片；下载 ZIP 解压后，文件内容也应与被复制的源文件一致。

## 2. 明确筛选条件

在协作汇总中选条件，结合文件名查询定位结果。查询针对所选条件的完整结果集；汇总列表最多显示前 200 行，**批量导出范围包含全部匹配结果**，不被这 200 行显示截断。

| 模式 | 含义 |
|---|---|
| 任意人收藏 | 至少 1 名筛选人收藏 |
| 至少 N 人推荐 | 收藏人数大于或等于 N；N 是人数阈值，不是分数 |
| 有备注／标签 | 任意筛选人填写了备注或至少一个标签 |
| 全队未审 | 没有任何筛选人标为已审；不等于仅“我未审” |
| 全部样本 | 当前数据集全部样本，可继续叠加文件名查询 |

收藏人数依据独立身份计数，不会因一个人重复点击而累计多票；导出反映预览所确认的条件，不表示系统自动判定哪个方法更好。筛选结果可能为 0，此时应调整条件后再导出。

## 3. 先预览，再导出

1. 确认当前模式、N 和查询，检查匹配样本数量。
2. 在“团队汇总”点击“批量导出原图”，再点“预览导出范围”，查看样本／方法数量、存在／缺失文件及体积估计。
3. 默认选全部方法，**主界面隐藏的方法列仍包含在内**；需要时明确取消某些方法。
4. 检查缺失和失败提示。少文件的方法不会由其他图片补位。
5. 确认后点击“开始批量导出”；查看进度，完成后核对报告。取消保留已完成副本与不完整报告。ZIP 若尚未完成，不提供不完整压缩包下载；已暂存副本保留在主机的受控批次中，不应当作访问者已下载完成。

不要把汇总中可见的前 200 行当作全部筛选结果，也不要把方法可见性当作导出选择。以批量导出预览中的数量和方法清单为准。

## 4. 主机：复制到新批次

主机选择“复制到本机目录”，选一个**已存在且可写的输出目录**；程序只在其下创建新的批次，不覆盖原图、同名旧文件或已有批次。也可选择“生成 ZIP 下载”。方法文件夹按显示名称生成跨 Windows／macOS 的安全名称；非法字符、保留名和冲突由映射表说明，原始方法目录不改名。

目标不能在原图目录内部；源码、索引和数据库目录也受到保护，可选工作区 `exports` 或项目外的可写目录。目录选择对话框新建文件夹后再选中，也符合“已存在”的要求。

完成弹窗中“复制”取得单个方法绝对目录，“一键复制全部目录”取得多行绝对路径。“复制时加双引号”适合接收方明确要求带引号的格式，普通目录选择通常不用引号。`paths.txt` 保存相对方法文件夹名，不能把它单独当绝对目录粘贴；后来重开时用批次绝对路径拼接，或在成功弹窗填写本机根目录后复制。映射见 `report.json`，移动后要重新准备。

结构示意，实际命名以结果为准：

```text
新批次/
  Input/...
  Baseline/...
  Ours/...
  paths.txt                相对方法目录，不是绝对路径
  report.json
  README.md                本批次使用说明
  manifest.csv             带表头／BOM的完整审计清单
  MulimgViewer.csv          主机复制时：无表头、绝对路径
  mulimg-relative.csv       ZIP时：相对位置参考，不直接导入
```

## 5. 访问者：下载 ZIP 后在自己的电脑使用

远程访问者不能打开主机的系统文件选择器，也不能指定一个主机盘符作为自己的保存位置。选择下载 ZIP，由浏览器保存到访问者电脑；**先完整解压，再准备本机路径，再导入 MulimgViewer**。

点击“下载原图 ZIP”，完整解压。回到成功弹窗，在“你电脑上已解压的批次目录”填写**批次目录本身**的绝对路径：打开它应直接看到各方法文件夹，不是再包一层批次目录的父目录。然后使用“下载 MulimgViewer 导入 CSV”；方法路径也按这个本机根目录重新生成。输入路径首尾的双引号会去掉，无需手工编辑 CSV 的引号规则。

ZIP 内相对位置仅描述关系，不能假定 MulimgViewer 以 CSV 所在目录为基准。移动、跨电脑或 Windows／Mac 互迁后，重新填写本机批次路径，再下载兼容 CSV；只更改清单，不修改图像内容。不需要为了这一浏览器步骤安装 Python。

![2.2 ZIP 完成与结果计数](screenshots/batch-result.png)

Mac 路径、Windows 盘符与网络主机路径彼此不能混用。浏览器下载位置由浏览器控制；页面无法无授权猜测解压目录。主机复制成功不代表访问者已经获得那些本地文件。

## 6. 在 MulimgViewer 中打开

### 相同文件名且结果完整

可以使用 MulimgViewer 的并行目录模式，从成功弹窗或本机 `paths.txt` 获取方法目录。先导入少量样本检查每行确为同一样本，再调整布局。小库不要求加载原始数万张图。

### 扩展名不同、名称有安全映射或需要明确对应

使用批次生成的 MulimgViewer 专用 CSV，在其 **Image File List** 模式打开。该 CSV 是无表头矩形网格：每行一个样本、每列一个方法、每格一个存在的本机图片路径。不要加入样本编号列或方法名标题行；UTF-8 不带 BOM。格式依据官方读取代码核对。[MulimgViewer 官方 CSV 读取实现](https://github.com/nachifur/MulimgViewer/blob/master/src/mulimgviewer/src/data.py)

为防止缺项导致外部工具错位，兼容 CSV 只纳入所选方法全部复制成功、后缀为 `.png/.jpg/.jpeg/.bmp/.tif/.tiff` 的完整行；其余样本在报告／完整对应清单中说明。其他格式仍可原样复制，但不会进入这个兼容矩形。复制成功不等于完整像素解码，外部工具仍可能遇到源文件本身损坏。不要把带表头的 `manifest.csv` 当图片列表打开，也不要把 `.jpg` 直接改名为 `.png`。

当前核对代码的读取与 GUI 选择入口没有承诺 CSV 相对路径基准为 CSV 父目录，因此本项目要求准备**当前电脑绝对路径**后再导入；这是据代码作出的兼容设计，不是对所有 MulimgViewer 版本的 GUI 实测结论。[官方文件列表入口](https://github.com/nachifur/MulimgViewer/blob/master/src/mulimgviewer/src/main.py)

## 7. 完成后检查什么

- `report.json` 中的计划、成功、Missing 与失败计数，安全名称映射；每项状态、字节数和 SHA256 可用于后续核对。完整行／排除行数量也会在完成弹窗显示。
- 各方法文件夹是否是你选择的方法；源目录与源文件是否仍保持原样。
- MulimgViewer CSV 是当前设备的路径，移动或解压后已经重新准备。
- 导入后逐行检查样本和列顺序，缺项不以另一张结果替代。

大规模复制仍消耗磁盘与网络，ZIP 也不是零成本操作。应先缩小筛选范围、查看体积并留出空间。兼容性按本次核对的官方代码设计，尚未实际执行的 MulimgViewer GUI、Mac 实机或校园网第二设备项目，以 `TESTING.md` 为准，不将代码核对写成已运行通过。

2.2 当前保护上限为 250,000 个计划文件、ZIP 原图总量 8GiB、目录复制 256GiB，并检查剩余空间。它们限制导出任务，不是把汇总列表截断成前 200 项；超过时应主动缩小范围或分批。流式文件复制／ZIP 不读取全库像素，但仍会占用主机磁盘吞吐。

## 8. 已执行的 2.2 小批次验证

合成 310 样本、4 方法，3 名筛选人分别收藏 310／240／205 个样本。N=3 时预览 205 样本、819 个可复制文件、1 个 Missing；目录实际复制 819 文件，逐个 SHA256 与源一致，兼容 CSV 为 204 完整行 × 4 列，无表头／BOM。ZIP 含 819 张原图，完整性检查通过且未夹带主机路径；4 个方法路径实际复制到剪贴板通过。

另在当前 1,503 样本、10 方法真实数据集上使用隔离标记副本，按至少 2 人收藏筛出 20 样本，复制 200 个原图并全部核对 SHA256 一致；含验证 5.516 秒。这是特定小批次的结果，不是全库吞吐保证。完整自动测试计数及未测平台以 `TESTING.md` 最终记录为准。
